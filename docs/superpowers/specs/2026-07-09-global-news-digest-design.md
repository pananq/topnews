# 全球十大新闻网站设计

## 背景与目标

制作一个部署在 GitHub Pages 上的静态新闻网站。网站每天早上 8 点自动更新过去 24 小时全球最热门的十大新闻事件，页面用中文展示。新闻来源应覆盖多语言媒体，例如英文、法文、德文、日文等来源；外文内容需要转换为中文标题与摘要，并保留原文链接，方便用户继续阅读来源报道。

目标体验是“每日全球新闻简报”：打开首页即可看到当天十大新闻事件，能按政治、科技、经济等分类快速筛选，也能查看每条事件的来源和热度依据。

## 已确认需求

- 部署平台：GitHub Pages。
- 更新频率：每天早上 8 点，北京时间。
- 内容窗口：过去 24 小时。
- 展示语言：中文。
- 新闻来源语言：不限，优先多地区、多语言来源。
- 新闻形式：十大“事件”，不是十篇单独文章；同一事件的多篇报道应聚合。
- 来源呈现：每条事件保留原始新闻链接列表。
- 推荐方案：RSS 多源聚合 + GitHub Actions 定时生成 + AI 中文摘要。

## 范围

首版包含：

- 静态前端页面，直接读取 `data/latest.json`。
- 示例数据文件，保证 GitHub Pages 首次部署后可正常展示。
- RSS 新闻源配置。
- 每日数据生成脚本。
- 事件聚类、热度排序、分类与中文摘要生成。
- GitHub Actions 工作流，每天北京时间 8 点自动运行。
- 数据校验与核心脚本测试。

首版不包含：

- 用户账号、收藏、评论或个性化推荐。
- 后端服务或数据库。
- 实时新闻推送。
- 付费新闻 API 依赖。
- 复杂人工编辑后台。

## 架构

系统分为三层：

1. 前端静态站
   - 使用 GitHub Pages 托管。
   - 首页读取 `data/latest.json` 并渲染十大新闻事件。
   - 提供分类筛选、状态提示、来源链接和更新信息。

2. 数据生成脚本
   - 在 GitHub Actions 中运行。
   - 抓取多语言 RSS 源。
   - 过滤过去 24 小时内的文章。
   - 聚合同一事件、计算热度、选出前 10 个事件。
   - 将结果写入 `data/latest.json`。

3. AI 摘要模块
   - 使用 GitHub Secrets 中的 API Key。
   - 对入选事件生成中文标题、中文摘要、分类、影响地区和简短热度说明。
   - API Key 不进入前端 bundle，也不写入生成后的 JSON。

## 数据源

首版使用公开 RSS 源，配置集中放在脚本可读取的源列表中。候选来源包括：

- 综合国际：Reuters、AP、BBC、Al Jazeera、France 24、DW、The Guardian、CNN、NPR。
- 地区来源：NHK、The Japan Times、Korea Herald、South China Morning Post 等。
- 科技与商业：The Verge、TechCrunch、Wired、Financial Times 可用 RSS、CNBC、Bloomberg 可用 RSS。
- 主题来源：气候、健康、体育、娱乐等公开 RSS。

源列表应支持启用/禁用、语言、地区、权重和分类提示字段。若某些 RSS 源不可用或限制较多，可以在后续维护中替换，不影响前端。

## 数据流

每日工作流：

1. GitHub Actions 在北京时间每天 8 点触发。
2. 脚本读取 RSS 源配置并并发抓取。
3. 标准化文章字段：标题、摘要、链接、来源、发布时间、语言、地区、初始分类。
4. 丢弃发布时间不在过去 24 小时内的文章。
5. 根据标题、摘要、关键词和链接域名进行事件聚类。
6. 为每个事件计算热度分数。
7. 选择分数最高的 10 个事件。
8. 调用 AI 摘要模块生成中文结构化结果。
9. 校验 JSON schema。
10. 写入 `data/latest.json` 并提交回仓库。

## 事件聚类

聚类目标是把同一事件的多篇报道合并为一个事件。首版采用轻量规则，避免引入过重依赖：

- 对标题和摘要做规范化：小写化、去标点、去停用词、提取关键词。
- 使用关键词重叠、标题相似度、来源时间接近度和实体词重叠作为聚类信号。
- 相似度超过阈值时合并到同一事件。
- 每个事件最多保留 5 个代表性来源链接，优先保留不同媒体和不同地区来源。

后续如需要更高质量，可以替换为 embedding 聚类，但首版不依赖向量数据库。

## 热度排序

事件分数由以下信号组成：

- 来源数量：报道该事件的不同来源越多，分数越高。
- 来源权重：国际通讯社、主流公共媒体和高可信专业媒体权重更高。
- 跨地区覆盖：来自不同地区媒体的报道越多，分数越高。
- 新鲜度：发布时间越接近统计窗口后段，分数略高。
- 主题重要性：政治、安全、重大灾害、科技产业重大事件等关键词可适度加权。

排序结果是自动化近似，不声称等同于人工新闻编辑判断。页面会展示来源数量、覆盖地区和简短热度说明，帮助用户理解榜单依据。

## 分类

首版分类包括：

- 全部
- 政治
- 科技
- 经济
- 国际
- 安全
- 气候
- 社会
- 体育
- 娱乐

每条事件由 AI 摘要模块给出一个主分类。RSS 源配置和关键词规则可作为分类提示，防止摘要模型自由发挥过多。

## 前端体验

首页就是核心产品，不做营销页。

页面顶部显示：

- 站点名。
- 最后更新时间。
- 覆盖窗口：过去 24 小时。
- 数据状态：正常、使用上一版数据、样例数据或更新失败提示。

主体区域：

- 十大新闻事件列表。
- 每条新闻显示排名、分类标签、中文标题、2-3 句中文摘要、影响地区、热度信号和来源链接。
- 分类筛选使用紧凑的标签/分段控件。
- 桌面端使用主列表加侧栏概览。
- 移动端使用单列布局。

视觉风格：

- 新闻编辑室风格，克制、清晰、信息密度高。
- 避免营销页式大 Hero、夸张渐变和装饰性视觉。
- 保证移动端标题、摘要和按钮不溢出。

## 失败处理

- RSS 单源失败：记录警告，继续处理其他来源。
- 多数来源失败：生成结果时标记为部分数据。
- AI 摘要失败：保留聚类结果并使用规则生成的临时中文字段，或继续使用上一版 `latest.json`。
- JSON 校验失败：不覆盖上一版数据，Actions 失败并保留日志。
- 前端加载失败：显示可读错误状态和最后可用数据提示。

## GitHub Actions

工作流触发方式：

- 定时触发：北京时间每天 8 点，对应 UTC 0 点。
- 手动触发：支持 `workflow_dispatch` 便于调试。

工作流步骤：

1. Checkout 仓库。
2. 安装依赖。
3. 运行测试。
4. 生成新闻数据。
5. 校验 `data/latest.json`。
6. 若数据有变化，提交回仓库。

需要的仓库配置：

- GitHub Pages 指向主分支或指定 Pages 分支。
- GitHub Secret：AI 摘要服务 API Key，例如 `OPENAI_API_KEY`。
- Actions 需要有提交回仓库的权限。

## 测试策略

- 数据 schema 测试：确保 `latest.json` 字段完整、类型正确、链接合法。
- RSS 解析测试：用 fixture 覆盖不同发布时间、语言和缺失字段。
- 聚类测试：同一事件多标题应合并，不同事件不应误合并。
- 排序测试：来源数量、地区覆盖和新鲜度影响分数。
- 前端状态测试：正常数据、空数据、样例数据、旧数据、加载失败。
- 构建测试：确保 GitHub Pages 静态输出可部署。

## 风险与缓解

- RSS 来源不稳定：源列表可配置，单源失败不阻塞全量更新。
- 自动排序不完美：页面展示热度信号，并保留来源链接供用户判断。
- AI 摘要成本：只对前 10 个聚合事件摘要，不对所有文章逐篇摘要。
- AI 摘要可能出错：摘要提示要求只基于来源内容，不编造未提供事实。
- GitHub Actions 定时存在延迟：页面显示实际生成时间，而不是假设准点完成。
- 新闻版权风险：页面只展示原创中文摘要和来源链接，不转载全文。

## 验收标准

- GitHub Pages 打开首页即可看到中文十大新闻事件列表。
- 页面显示最后更新时间和过去 24 小时窗口。
- 用户能按分类筛选事件。
- 每条事件至少包含中文标题、中文摘要、分类、影响地区、热度信号和来源链接。
- GitHub Actions 可手动运行，并能在成功后更新 `data/latest.json`。
- 定时任务设置为北京时间每天 8 点更新。
- 无 API Key 时，项目仍可用样例数据在本地和 Pages 上展示。
- 测试命令通过。
